# ConfigStore.h — Конфигурация и EEPROM

## Назначение

Хранение конфигурации WiFi, SMTP, счётчиков, адресов DS18B20 и расписания отчётов в EEPROM.

## Структура `ConfigData`

| Поле | Тип | Описание |
|------|-----|----------|
| `magic` | `uint16_t` | `0x5A4B` — проверка валидности |
| `wifiSSID` | `char[32]` | SSID |
| `wifiPass` | `char[64]` | Пароль |
| `smtpHost` | `char[32]` | SMTP-сервер |
| `smtpPort` | `uint16_t` | Порт SMTP |
| `smtpEmail` | `char[48]` | Email отправителя |
| `smtpPass` | `char[48]` | Пароль |
| `smtpRecipient` | `char[48]` | Email получателя |
| `meterHotM3` | `float` | Показания ГВС (м³) |
| `meterColdM3` | `float` | Показания ХВС (м³) |
| `litersPerPulseHot` | `float` | Л/импульс (ГВС) |
| `litersPerPulseCold` | `float` | Л/импульс (ХВС) |
| `sensorAddrs[4][8]` | `uint8_t[4][8]` | Адреса DS18B20 |
| `sensorAddrsValid` | `bool` | Валидность адресов |
| `reportHour/Minute` | `uint8_t` | Время отчёта |
| `reportSchedule` | `uint8_t` | 0=daily, 1=weekly, 2=monthly |
| `reportDay` | `uint8_t` | День недели/месяца |
| `debounceClosedMs` | `uint16_t` | Антидребезг замыкания геркона, мс (0 = по умолчанию) |
| `debounceOpenMs` | `uint16_t` | Антидребезг размыкания геркона, мс (0 = по умолчанию) |
| `deviceName` | `char[32]` | Имя устройства (пустое = сгенерировать из MAC) |
| `mqttEnabled`, `mqttHost`, `mqttPort`, `mqttUser`, `mqttPass`, `mqttIntervalSec` | — | Блок MQTT, добавлен в конец структуры |
| `filterEnabled` | `bool` | Защита осмотического фильтра включена |
| `filterTempOnC` | `float` | Верхний порог: реле включается, клапан закрыт |
| `filterTempOffC` | `float` | Нижний порог: реле отключается |
| `filterRelayActiveLow` | `bool` | Управляющий уровень модуля реле |
| `filterNotifyMqtt` | `bool` | Показывать фильтр в Home Assistant |
| `filterNotifyEmail` | `bool` | Слать письма о событиях фильтра |
| `filterMetricsEnabled` | `bool` | Отдавать серии фильтра в `/metrics` |
| `reportEnabled` | `bool` | Общий выключатель плановых писем |

> Поля антидребезга заняли 4 байта из резерва — размер `ConfigData` не изменился, поэтому существующие настройки в EEPROM читаются без сброса.

> **`deviceName` добавлено в конец структуры намеренно.** Смещения всех прежних полей не изменились, поэтому существующие настройки читаются как есть, а `magic` остаётся валидным. В байтах за прежним размером структуры лежит `0xFF` из стёртой flash — санитайзер при загрузке превращает это в пустую строку, то есть в «имя по MAC». Проверено на устройстве: после расширения структуры SSID, пароль и показания счётчиков уцелели.

> **Блок фильтра — третий, добавленный в конец структуры**, и проверяется отдельным санитайзером `sanitizeFilterFields()`. Отдельным потому, что у пользователя, прошившегося на промежуточной версии, блок MQTT уже инициализирован, а этот ещё нет — одна общая проверка приняла бы такую EEPROM за полностью валидную.
>
> Признак нетронутой flash здесь — **NaN**: `0xFFFFFFFF`, прочитанные как `float`, дают именно его, а сравнение `!(v > 0)` ловит и NaN, и ноль. Для `bool` тот же `0xFF` читается как `true`, поэтому `reportEnabled` при миграции остаётся включённым — и это правильно: обновление не должно молча отключить плановые отчёты тем, кто ими уже пользуется. А вот `filterEnabled` санитайзер явно ставит в `false`: без реле на ноге защита бессмысленна, и включать её за пользователя нельзя.

## Методы

| Метод | Описание |
|-------|----------|
| `begin()` | Инициализация EEPROM, загрузка |
| `load()` | Чтение из EEPROM, автоинициализация если данные невалидны |
| `save()` | Запись в EEPROM |
| `resetDefaults()` | Сброс к значениям по умолчанию |
| `setSensorAddr(index, addr)` | Сохранение адреса DS18B20 |
| `getSensorAddr(index)` | Получение адреса (EEPROM или secrets.h) |

> `saveMeters()` удалён: он побайтно повторял `save()`, и `loop()` вызывал обе функции подряд — две одинаковые записи EEPROM вместо одной.
