# FailsafeOTA.h — Контроль успешности OTA

## Как OTA работает на ESP8266 на самом деле

Это важно понимать, потому что раньше модуль был построен на неверной модели.

**A/B-слотов на ESP8266 нет.** Штатный механизм Arduino-ядра:

1. `ArduinoOTA` принимает образ и пишет его во временную область flash — сразу под файловой системой (`Updater.cpp`, `updateStartAddress = _FS_start - roundedSize`)
2. `Updater::end()` записывает в RTC команду загрузчика `eboot`: `ACTION_COPY_RAW` (откуда, куда, сколько)
3. При перезагрузке `eboot` **копирует образ в `0x00000`**, поверх старой прошивки, и запускает его

После шага 3 старой прошивки не существует. **Откатываться некуда.**

### Почему автоматический откат вообще невозможен без замены загрузчика

Команду `eboot` записывает работающее приложение. Если новая прошивка падает до `loop()`, она физически не может попросить откат — некому. Закрыть этот сценарий может только сам загрузчик, считая неудачные загрузки. Это замена `eboot`, который лежит по `0x0000` и шьётся исключительно по USB — ошибка в своём загрузчике означает мёртвую плату без возможности починки по WiFi.

Поэтому модуль не обещает отката.

## Что модуль делает

Даёт видимый признак того, что новая прошивка дожила до `loop()` и принимает команды:

1. `ArduinoOTA.onEnd()` → `updateFirmware()` — флаг `RTC_MAGIC_FIRST_BOOT` в RTC memory
2. Новая прошивка стартует, `begin()` видит флаг → `_pending = true`, флаг меняется на `RTC_MAGIC_RETRY`
3. В SPA появляется баннер с обратным отсчётом (5 минут)
4. Пользователь подтверждает: `/confirm`, кнопка Confirm или Telnet-команда `confirm` → `RTC_MAGIC_NORMAL`
5. Подтверждения нет 5 минут → **одна** перезагрузка (вдруг прошивка «полуживая» и рестарт вернёт её в строй)
6. После этой перезагрузки `begin()` видит `RTC_MAGIC_RETRY` → пишет предупреждение в лог и больше не перезагружается

Шаг 6 — защита от bootloop. Раньше модуль мог перезагружаться бесконечно.

## RTC: почему смещение 32, а не 0

Флаг пишется по `RTC_FLAG_OFFSET = 32` (байт 128), и это не косметика.

Первые 128 байт пользовательской RTC-памяти занимает команда загрузчика `eboot`, которую `Updater::end()` записывает при OTA. Запись флага в блок 0 затирала её поле `magic`, загрузчик отбрасывал команду как невалидную, и образ из временной области не копировался — плата поднималась на старой прошивке, хотя `espota` рапортовал `Result: OK`.

Подробный разбор — в [pitfalls.md, раздел 16](../pitfalls.md).

## Состояния RTC

| Значение | Смысл |
|----------|-------|
| `RTC_MAGIC_NORMAL` (0x00000000) | Обычный старт, ничего не ждём |
| `RTC_MAGIC_FIRST_BOOT` (0xDEAD0001) | Первый старт после OTA, ждём подтверждения |
| `RTC_MAGIC_RETRY` (0xDEAD0002) | Была перезагрузка по таймауту, повторять не будем |

> RTC memory переживает soft-reset, но **не** потерю питания. После выдёргивания питания баннер подтверждения не появится — это ожидаемо.

## Методы

| Метод | Описание |
|-------|----------|
| `begin()` | Проверка RTC-флага, установка `_pending` |
| `handle()` | Проверка таймаута в `loop()` |
| `updateFirmware()` | Вызывается из `ArduinoOTA.onEnd()` — выставляет флаг |
| `confirm()` | Подтверждение прошивки |
| `isPending()` | Ждём ли подтверждения |
| `remainingSec()` | Секунд до перезагрузки |

## Что удалено и почему

| Было | Почему удалено |
|------|----------------|
| `getCurrentSlot()` | Всегда возвращал 1: код отображается в окно `0x402xxxxx`, а маска `& 0x3FFFFF` давала значение заведомо больше `0x101000` |
| `SLOT_A_IMAGE_ADDR` / `SLOT_B_IMAGE_ADDR` | По этим адресам образов не было никогда |
| `rollback()` | Писал `ACTION_LOAD_APP` на адрес без образа — это не откат, а перезагрузка через сбой |
| `forceRollback()` | То же самое, вызывался вручную |
| `upload_script.py` | Шил прошивку в `0x10000` и `0x101000`, оставляя `0x0` пустым — плата бы не загрузилась |

## Если прошивка оказалась нерабочей

Единственный путь — перепрошивка по USB:

```bash
pio run --target upload --upload-port COM3
```
