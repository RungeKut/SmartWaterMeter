# TelnetSerial.h — Telnet-консоль

## Назначение

Логи прошивки по WiFi (TCP:23) и консоль команд. До 4 одновременных клиентов.

## Как работает

Класс реализует интерфейс `LogSink` из [Log.h](log.md) и регистрируется приёмником логов:

```cpp
Log.setSink(&telnet);
telnet.begin();
```

Всё, что прошивка пишет через `Log.print/printf/println`, накапливается построчно (буфер 512 байт) и по `\n` уходит всем подключённым клиентам.

## Что НЕ попадает в Telnet

Низкоуровневый вывод SDK — сообщения WiFi-стека (`scandone`, `state: 0 -> 2`). Они остаются только на USB-Serial.

Раньше модуль ставил хук `os_install_putc1()` и документация обещала «перехват всего вывода». Фактически было наоборот: хук ловил **только** вывод SDK, а логи самой прошивки (`Serial.printf`) шли напрямую в UART мимо него. Вдобавок предыдущий обработчик не сохранялся, поэтому вывод SDK пропадал и из USB-Serial. Хук убран — писать в TCP-сокет из контекста SDK небезопасно.

## Команды

| Команда | Описание |
|---------|----------|
| `help` | Список команд |
| `status` | WiFi, IP, аптайм, heap |
| `reset` / `restart` | Перезагрузка |
| `heap` | Свободная память |
| `uptime` | Время работы |
| `confirm` | Подтверждение прошивки после OTA |

`status` показывает IP только в STA-режиме и адрес точки доступа только когда AP действительно поднята (`WiFi.getMode() & WIFI_AP`). Раньше печатались оба поля всегда, включая `0.0.0.0`.

## Методы

| Метод | Описание |
|-------|----------|
| `begin()` | Запуск TCP:23 |
| `handle()` | Вызов в `loop()`: приём клиентов, команды |
| `logWrite(buf, size)` | Реализация `LogSink` — вызывается из `Log` |

## Безопасность

Простое текстовое соединение, без пароля. Только для доверенной сети.

По этой же причине `ConfigStore::load()` больше не печатает пароль WiFi — раньше он уходил в лог открытым текстом и был виден любому, кто подключился по Telnet.
